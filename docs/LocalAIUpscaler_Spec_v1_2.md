# Local AI Upscaler — Codex 개발 작업 명세서

- 문서 유형: 구현 지시용 작업 명세서 (Markdown)
- 버전: 1.2
- 작성일: 2026-11-11
- 개발 에이전트: **OpenAI Codex**
- 실행 플랫폼: Windows 데스크톱(x64). 특정 GPU 모델이나 VRAM 용량을 구현 전제로 삼지 않는다.
- 주 UI: **C# WPF / .NET 10**
- 이미지 처리: **Python Worker + PyTorch + Real-ESRGAN x4plus**
- 실행 원칙: **완전 로컬, 추론 시 인터넷 접속 불필요**
- 제공 범위: **동작 가능한 전체 소스, 테스트, 빌드/배포 스크립트, 실행 문서**

> 이 문서는 Codex의 구현 기준이다. 성능 예측, 예상 처리 시간, 벤치마크 목표 및 성능 수치 추정은 이 명세의 범위에서 제외한다. 필요한 기능을 누락시키지 않되, 이미지 *뷰어* 기능을 과도하게 확장하지 않는다.

## 1. 목표와 설계 원칙

### 1.1 프로젝트 목표

개인 사용자가 로컬 폴더의 이미지를 빠르게 탐색하고, 큰 프리뷰로 확인한 뒤 선택한 이미지를 **Real-ESRGAN x4plus로 4배 업스케일링**하는 Windows 데스크톱 응용 프로그램을 제작한다. 파일 탐색 및 프리뷰 흐름은 **FastStone Image Viewer의 브라우저형 레이아웃을 참고**하되, UI는 독자적인 **미니멀·모던 디자인**으로 구현한다.

### 1.2 핵심 원칙

1. **탐색 중심 UI:** 폴더 트리 → 파일 썸네일 → 대형 프리뷰 → 단일 이미지 또는 폴더 단위 업스케일링의 흐름을 제공한다.
2. **원본 보호:** 원본 파일 수정·덮어쓰기는 금지한다.
3. **작업과 UI 분리:** WPF는 탐색·표시·작업 관리에 집중하고 Python Worker가 추론을 수행한다.
4. **하드웨어 전환:** 자동 / NVIDIA CUDA GPU / CPU 실행 모드를 제공한다.
5. **모델 1종만 탑재:** 1차 릴리스는 `RealESRGAN_x4plus`만 지원한다. 향후 엔진을 추가할 수 있는 인터페이스만 설계한다.
6. **오프라인 실행:** 설치·모델 준비 후에는 네트워크 없이 모든 핵심 기능이 작동한다.
7. **사용성과 안정성:** 탐색·프리뷰는 비동기로 처리하고, 업스케일 작업 중에는 모달 진행 창에서 상태를 표시하며 메인 창 조작을 제한한다.

### 1.3 범위 제외

- 성능 예상치, 처리 시간 예측, 벤치마크 수치 및 벤치마크 개발 작업
- 이미지 편집기 기능(자르기, 회전 저장, 보정, 색상 편집, 레이어 등)
- FastStone의 기능 복제. 참고 범위는 **폴더 트리, 썸네일, 선택 이미지 프리뷰의 3영역 배치**로 한정
- 얼굴 복원(GFPGAN), SwinIR, NCNN/Vulkan, ONNX 등 추가 추론 엔진 구현
- 클라우드 추론, 로그인, 계정 관리, 자동 업데이트, 원격 분석
- 동영상 업스케일링, RAW 디코딩, 애니메이션 GIF의 전체 프레임 처리

## 2. UI/UX 명세 — 미니멀 모던 이미지 브라우저

### 2.1 디자인 방향

- FastStone Image Viewer의 **탐색형 공간 구성**을 참고한다. 구체적 아이콘·로고·스킨·시각 자산은 복제하지 않는다.
- 기본 테마는 **다크 모드**, 선택적으로 라이트 모드 지원(1차 구현 시 공용 테마 리소스 구조 확보).
- 무채색 배경, 절제된 강조색 1종, 얇은 구분선, 단순한 아이콘, 과하지 않은 둥근 모서리.
- 텍스트 중심의 명료한 도구 모음, 일관된 간격과 타이포그래피; 불필요한 장식/애니메이션 배제.
- 화면 폭 변화 시 패널 리사이즈 가능. **최소 지원 창 크기 1100×700**, 일반 데스크톱 사용 시 권장 1440×900 이상.
- Windows DPI 배율(100/125/150/200%) 및 키보드 탐색을 고려한다.

### 2.2 메인 창 기본 레이아웃

```text
┌──────────────────────────────────────────────────────────────────────────────────┐
│ AI Upscaler                                     [폴더 열기] [새로고침] [설정]       │
├──────────────────────────────────────────────────────────────────────────────────┤
│ ◀  ▶  ↑   C:\Pictures\Trips\2026                                             │
├─────────────────┬────────────────────────────────────────┬───────────────────────┤
│ 폴더 트리       │             이미지 프리뷰              │ 업스케일 설정         │
│                 │                                        │                       │
│ 내 PC           │          [선택 이미지 미리보기]       │ Real-ESRGAN x4plus    │
│   C:            │                                        │ Auto / CUDA / CPU     │
│   D:            │        화면 맞춤 / 확대 / 축소        │ 출력 폴더 선택        │
│   Pictures      │                                        │                       │
│     Trips       │                                        │ [현재 이미지 실행]    │
│                 │                                        │ [현재 폴더 실행]      │
├─────────────────┼────────────────────────────────────────┴───────────────────────┤
│                 │ [썸네일 1] [썸네일 2] [썸네일 3] ...                            │
├─────────────────┴────────────────────────────────────────────────────────────────┤
│ 선택 이미지: photo.jpg / 1920×1080   |   엔진 상태: 준비됨                       │
└──────────────────────────────────────────────────────────────────────────────────┘
```

**배치 원칙:** 폴더 트리, 썸네일 목록, 큰 프리뷰에 집중한다. 이미지 편집·정교한 관리 도구·상시 작업 큐 패널은 추가하지 않는다. 업스케일 진행률은 메인 창이 아닌 **별도 모달 진행 창**에서 표시한다.

### 2.2.1 업스케일 진행 모달

```text
┌──────────────────────────────────────────────────────────┐
│ 이미지 업스케일링                                        │
│                                                          │
│ 처리 범위: 현재 폴더 (12개 이미지)                       │
│ 현재 파일: photo_03.jpg                                  │
│ 전체: 3 / 12                                              │
│ [████████████░░░░░░░░] 60% (현재 파일)                   │
│ 완료 2 · 실패 0 · 남음 10                                 │
│                                                          │
│                                      [작업 취소]          │
└──────────────────────────────────────────────────────────┘
```

- 업스케일 시작 시 `ShowDialog()` 또는 동등한 WPF 모달 방식으로 표시한다.
- 진행 중 메인 창의 폴더 이동, 파일 선택, 설정 변경, 추가 실행을 **차단**한다. 모달 창 자체와 취소 버튼은 반응 가능해야 한다.
- Python 추론은 백그라운드 Worker에서 실행하며 WPF UI 스레드를 블로킹하지 않는다.
- 진행률, 현재 파일명, 전체 파일 수, 완료/실패 수를 표시한다. 실제 진행률 산정이 불가능한 단계는 무한 진행 표시를 사용한다.
- **취소 버튼**으로 현재 작업과 남은 폴더 작업을 중단 요청하며, 종료를 확인할 때까지 모달을 닫지 않는다.
- 완료/취소/실패 후 간단한 결과 요약을 제공한 다음 모달을 닫고 메인 창 조작을 복원한다.
- 창 우측 상단 닫기 및 Esc 동작은 진행 중 무단 종료가 아니라 취소 확인 절차로 연결한다.
- 메인 창을 종료하려 할 때도 진행 모달과 동일한 취소·정리 정책을 따른다.

### 2.3 상단 툴바/경로 표시

- **폴더 열기:** 네이티브 폴더 선택 대화상자로 탐색 시작 위치 변경.
- **이전 / 다음 / 상위 폴더:** 탐색 히스토리와 폴더 계층 이동.
- **주소 표시줄:** 현재 폴더 전체 경로 표시; 경로 직접 입력 후 Enter 이동.
- **새로고침:** 현재 폴더의 파일 목록 다시 스캔.
- **검색/필터:** 현재 폴더 안의 파일명 필터(부분 일치), 지원 이미지 형식만 보기.
- **설정 버튼:** 앱/엔진/출력 기본 설정으로 이동.
- 파일 탐색은 앱 내부에서 완결되며 외부 파일 탐색기를 필수로 실행하지 않는다.

### 2.4 좌측 폴더 탐색기

- Windows 드라이브와 사용자 접근 가능 폴더를 계층적으로 표시.
- 폴더 노드는 **지연 로딩(Lazy Loading)** 하여 대규모 디렉터리에서 초기 렌더링 지연 방지.
- 선택한 폴더의 지원 이미지 파일을 중앙 하단 썸네일 목록에 표시.
- 접근 권한 부족, 연결 해제된 드라이브, 존재하지 않는 경로에 대해 오류 메시지를 제공하고 UI가 종료되지 않도록 처리.
- 폴더 리프레시, 탐색 히스토리, 현재 선택 상태 유지(가능한 경우).
- 기본 정책: **현재 선택한 폴더의 직접 포함 이미지**를 표시한다. 하위 폴더 재귀 스캔은 1차 범위에서 제외한다.

### 2.5 이미지 썸네일 패널

- 현재 폴더의 이미지 썸네일을 그리드/가로 목록 형태로 표시한다.
- 클릭 시 선택 이미지가 중앙 프리뷰에 표시된다.
- 파일명 표시, 기본 정렬(파일명), 스크롤을 지원한다.
- 비동기 썸네일 로딩과 간단한 캐시를 사용한다.
- **다중 선택은 필수 요구사항이 아니다.** 업스케일 대상은 현재 선택한 이미지 1개 또는 현재 폴더의 이미지 전체다.
- 폴더 전환 시 이전 썸네일 로딩은 취소한다.

### 2.6 중앙 이미지 프리뷰 — 간소화

필수 기능만 제공한다.

- 선택 이미지 1개의 큰 프리뷰(기본 화면 맞춤).
- 확대/축소(휠 또는 +/-)와 화면 맞춤.
- 파일명 및 원본 해상도 표시.
- 로딩/손상 파일/미지원 형식에 대한 기본 안내.
- 완료 후 결과 파일을 선택하거나 열어 프리뷰할 수 있도록 한다.

**구현 제외:** 슬라이드쇼, 전체 화면 감상 모드, 히스토그램, EXIF 편집, 이미지 편집, 태그/평점, 파일 관리 도구, 복잡한 단축키 체계, 전용 원본-결과 비교 모드. FastStone에서 참고할 사항은 탐색 레이아웃뿐이다.

### 2.7 우측 업스케일 설정 패널

- 모델: `Real-ESRGAN x4plus` 고정 표시.
- 배율: 4배 고정.
- 하드웨어: `자동(CUDA 우선)`, `NVIDIA CUDA`, `CPU` 전환.
- 정밀도: 기본 Auto; CPU에서는 FP32 사용. 고급 설정에서 CUDA FP16/FP32 선택 가능.
- 타일: 기본 Auto; 고급 설정에서 수동 크기 지정 가능.
- 출력 경로 및 PNG/JPEG 출력 형식 설정.
- 두 가지 명확한 실행 버튼을 제공한다.
  - **현재 이미지 업스케일링:** 썸네일에서 선택한 이미지 한 개 처리. 선택이 없으면 비활성화.
  - **현재 폴더 업스케일링:** 현재 폴더에 직접 포함된 지원 이미지 파일 전체 처리. 하위 폴더는 포함하지 않음.
- 두 실행 버튼 모두 시작 전 작업 대상 수와 출력 위치를 확인하고 **동일한 모달 진행 창**을 표시한다.
- 출력 파일명 충돌 시 번호를 추가하고 원본을 덮어쓰지 않는다.
- 특정 GPU 모델, VRAM 크기 및 GPU별 최적화 수치는 UI/로직에 하드코딩하지 않는다.

### 2.8 하단 상태 영역

- 선택 이미지명 및 해상도, 현재 폴더, Python Worker 준비/오류 상태 등 간단한 정보만 표시한다.
- 상시 작업 큐/진행률/로그 패널은 배치하지 않는다.
- 필요 시 오류 상세 로그는 별도 파일 또는 단순한 진단 창에서 확인할 수 있다.

### 2.9 사용자 흐름

**단일 이미지 처리**
1. 폴더 탐색 → 썸네일에서 이미지 1개 선택 → 중앙 프리뷰 확인.
2. 출력 설정 확인 → `현재 이미지 업스케일링` 클릭.
3. 대상 확인 → 진행 모달 표시, 메인 창 조작 차단.
4. 완료 또는 취소 후 결과 요약 → 메인 창 복귀.

**폴더 단위 처리**
1. 폴더 탐색 → `현재 폴더 업스케일링` 클릭.
2. 해당 폴더의 지원 이미지 파일 목록을 스냅샷으로 확정하고 대상 개수 확인.
3. 모달에서 파일별 순차 처리, 현재 파일 및 전체 진행 상황 표시.
4. 실패 파일은 기록하고 가능한 경우 다음 파일로 진행. 취소 시 남은 파일 처리 중단.
5. 완료 후 성공/실패/취소 수와 출력 폴더를 안내하고 메인 창 복귀.

## 3. 기능 요구사항

### 3.1 이미지 파일과 탐색

- 필수 지원 입력: PNG, JPEG(JPG/JPEG), BMP, TIFF, WebP(선택한 라이브러리에서 확실하게 디코딩할 수 있도록 의존성 명시).
- 파일 목록은 지원 확장자만 기본 노출하되 확장자와 실제 파일 포맷 불일치를 검사한다.
- 이미지 파일을 WPF 창에 드래그 앤 드롭 시 해당 파일을 선택해 프리뷰한다(작업 자동 시작 없음).
- 폴더 드래그 앤 드롭 시 해당 폴더 탐색.
- 이미지 EXIF 회전 방향은 프리뷰와 추론 입력에서 일관되게 적용한다.
- 원본 알파 채널이 있는 경우 Real-ESRGAN의 알파 처리 가능성을 검증하고, 지원 불가 상황에서는 사용자에게 명확히 안내한다.

### 3.2 업스케일링

- 1차 엔진: `RealESRGAN_x4plus` 전용, 4× 출력.
- Python Worker는 모델을 한 번 로딩해 여러 작업에 재사용한다.
- 파일 경로를 받아 추론하고 결과를 디스크에 저장한다.
- CUDA 사용 가능 시 GPU 모드; CPU 강제 모드 가능.
- Auto 모드는 CUDA 우선, 불가능하면 CPU; 사용자가 CUDA를 명시적으로 강제하면 **자동 CPU 대체 없이 오류 표시**.
- GPU FP16 기본, CPU FP32 기본. CUDA FP32 선택 허용.
- OOM 발생 시 작업을 안전하게 정리하고 타일 크기를 줄여 제한적으로 재시도(예: 512→256→128). 실패 시 사용자에게 사유 안내.
- 폴더 작업은 대상 목록을 시작 시 확정하고 순차 처리한다. 동시 추론은 1개로 제한한다.
- 출력 파일은 임시 파일로 작성한 후 정상 완료 시 최종 이름으로 원자적 이동/교체 없이 확정. 중간 실패 파일은 제거.
- 작업 중에는 모달 창으로 메인 UI를 제한한다. 취소·창 닫기·앱 종료 시 Worker와 임시 파일 정리를 수행한다.

### 3.3 설정 영속화

- JSON 기반 사용자 설정: 최근 폴더, 출력 경로, 하드웨어, 정밀도, 타일 크기, 출력 형식, 창 레이아웃(패널 너비/높이), 테마.
- 설정 파일은 사용자별 앱 데이터 디렉터리(예: `%LocalAppData%/LocalAIUpscaler/`)에 저장.
- 설정 파일이 없거나 손상된 경우 안전한 기본값으로 복원.
- 경로에 한글/공백/특수문자가 포함되어도 정상 동작해야 한다.

### 4.3 WPF 패턴

- MVVM 패턴 사용; UI 코드 비하인드는 뷰 관련 최소 코드만 허용.
- 비동기 작업은 `async/await`, `CancellationToken`으로 취소 가능하게 설계.
- 이미지 탐색, 썸네일 로드, 프리뷰 디코딩, Worker IPC를 UI 스레드 밖에서 수행.
- `ObservableCollection` 변경은 UI Dispatcher에서 수행.
- 폴더/파일 리스트는 불필요한 재생성을 피하고, 썸네일 이미지 메모리 보유량을 제한.

### 4.4 Python Worker 및 IPC

- 별도 **장기 실행 Worker 프로세스**; 매 이미지마다 Python 프로세스를 다시 시작하지 않는다.
- stdin/stdout은 **UTF-8 JSON Lines**. stdout에는 프로토콜 JSON만 출력하고 라이브러리 로그는 stderr로 보낸다.
- 각 요청/응답에 `protocol_version`, `job_id`, `type` 필드 사용.
- 주요 명령: `hello`, `get_devices`, `load_model`, `upscale`, `cancel`, `shutdown`.
- 주요 이벤트: `ready`, `progress`, `completed`, `failed`, `cancelled`, `device_info`.
- 진행률은 타일 완료 수에 근거한 **추정 진행률**로 모달에 표시한다. 전체 폴더 진행은 완료 파일 수와 현재 파일 상태를 병행 표시한다; ETA는 필수 아님.
- Worker가 비정상 종료되면 앱은 오류를 기록하고 사용자가 재시작할 수 있게 한다.
- `cancel`은 타일 경계에서 협조적으로 처리하고, 응답이 없을 때 프로세스 종료 및 재시작 경로를 제공한다.
- 외부 프로세스 인수는 `ProcessStartInfo.ArgumentList` 등을 사용해 안전하게 전달하고, 파일 경로를 셸 명령 문자열에 직접 삽입하지 않는다.

#### JSON 요청 예시

```json
{"protocol_version":1,"type":"upscale","job_id":"job-001","engine":"realesrgan_x4plus","input":"C:\\Pictures\\input.png","output":"D:\\Upscaled\\input_x4.png","device":"auto","precision":"auto","scale":4,"tile_size":512,"tile_pad":16}
```

#### JSON 진행/완료 예시

```json
{"protocol_version":1,"type":"progress","job_id":"job-001","stage":"inference","progress":75}
{"protocol_version":1,"type":"completed","job_id":"job-001","output":"D:\\Upscaled\\input_x4.png","output_width":4096,"output_height":4096}
```

### 4.5 모델 및 향후 엔진 확장

- 초기 구현은 `RealESRGAN_x4plus` 한 종류만 동작하도록 한다.
- C# `IUpscaleEngine` 또는 이에 준하는 추상화와 Python `BaseEngine` 인터페이스 마련.
- 엔진 식별자(`engine_id`), 지원 장치, 지원 배율, 설정 스키마를 메타데이터로 노출.
- **실제 엔진 플러그인 검색/설치/마켓 기능은 구현하지 않는다.** 구조적 확장점만 제공한다.
- 모델 가중치와 의존성은 로컬에서 로딩하며 실행 중 자동 다운로드를 수행하지 않는다.

## 5. 파일 출력과 안전성

- 기본 출력 디렉터리: 사용자 선택 가능. 초깃값은 사용자 Pictures의 `Upscaled` 하위 폴더처럼 원본과 구분되는 위치.
- 출력 파일명: `<원본이름>_x4.png` 등. 충돌 시 `_x4_001`, `_x4_002` 순번 부여.
- 원본 파일은 읽기 전용 접근; **원본 경로에 직접 덮어쓰지 않는다**.
- 저장 전 출력 폴더 접근 가능 여부, 빈 공간, 유효한 파일명 검증.
- 결과 이미지와 프리뷰는 각각 별도 리소스 수명으로 관리하여 파일 핸들을 장시간 점유하지 않는다.
- 로그에 민감한 파일 경로가 포함될 수 있으므로 기본 로컬 저장, 외부 전송 금지.
- 오류는 사용자 친화적인 짧은 메시지와 기술 로그를 분리한다.

## 6. 배포 및 설치

### 6.1 개발 환경

- Windows x64, Visual Studio 또는 .NET SDK 10, Python(프로젝트에서 호환성을 검증한 고정 버전), PyTorch, Real-ESRGAN 관련 패키지.
- Python과 CUDA/PyTorch/BasicSR/Real-ESRGAN의 **호환되는 정확한 버전 조합을 구현 중 검증하고 잠근다**. 막연한 최신 버전 사용 금지.
- NVIDIA CUDA 실행에는 호환되는 GPU 드라이버 필요.

### 6.2 사용자 배포

- 사용자는 WPF 실행 파일을 시작하고 **Python을 별도로 설치하지 않아도** 되도록 Python 런타임 및 필요한 라이브러리를 패키징한다.
- 1차 배포는 **단일 설치 패키지 / 내부적으로 여러 파일**을 허용한다. 반드시 실제 파일 하나로 만드는 것을 요구하지 않는다.
- 모델 `.pth` 파일을 로컬에 배치하고 체크섬으로 무결성 확인.
- 정상 동작을 위해 필요한 모든 런타임 패키지를 제공한 상태에서 인터넷 연결 차단 테스트를 수행.
- 라이브러리 및 모델 라이선스, 저작자 고지, 재배포 조건을 검토하고 문서에 기록한다.

## 8. 수용 기준 (Definition of Done)

다음 항목을 만족해야 1차 완료로 판정한다.

1. Windows에서 WPF 프로그램이 정상 실행되며 메인 UI가 **폴더 트리 / 썸네일 목록 / 대형 이미지 프리뷰 / 업스케일 설정**으로 구성되어 있다.
2. 폴더 브라우징과 주소창 이동이 가능하며, 지정 폴더 이미지의 썸네일이 표시된다.
3. 이미지 선택 시 큰 프리뷰가 나타나고 화면 맞춤, 확대/축소, 이동이 작동한다.
4. 선택된 이미지 **한 개** 또는 **현재 폴더의 이미지 전체**를 대상으로 업스케일링할 수 있다(하위 폴더 제외).

6. Auto/CUDA/CPU 옵션 전환이 정상 동작하고 CPU 모드에서는 FP32로 처리된다.
7. 업스케일 시작 시 **모달 진행 창**이 나타나고 메인 창 조작은 제한된다. 모달 내 진행률·완료·실패·취소를 확인할 수 있으며 Worker 장애가 WPF 프로세스를 종료시키지 않는다.
8. 출력 폴더/결과 파일을 열거나 프리뷰할 수 있다. 복잡한 원본/결과 비교 UI는 필요하지 않다.
9. 원본을 변경하지 않으며 출력 파일명이 충돌해도 덮어쓰지 않는다.
10. 사용자 설정과 창 레이아웃이 저장·복원된다.
11. 필요한 런타임/모델을 포함한 배포물로 **인터넷 없이 추론**할 수 있다.
12. 전체 소스, 실행 가능한 빌드 스크립트, 테스트, README 및 배포 문서를 제공한다.
13. FastStone에서 **폴더 트리·썸네일·단일 이미지 프리뷰의 레이아웃만** 참고하고, 이미지 편집기나 고급 뷰어 기능은 구현하지 않는다.
14. 특정 GPU 제품명 또는 VRAM 용량을 필수 조건으로 가정하거나 하드코딩하지 않는다.

## 9. Codex 작업 지침

- 이 문서를 1차 개발의 **기준 명세(Single Source of Truth)**로 삼는다.
- UI를 먼저 정적 목업으로 끝내지 말고, 각 단계에서 실제 폴더 탐색·프리뷰·추론과 연결한다.
- Python과 WPF의 인터페이스는 명시적 JSON 계약으로 관리하고 변경 시 양쪽 테스트를 수정한다.
- 호환성이 불확실한 패키지 버전은 임의 확정하지 말고 실행 환경에서 검증 후 `requirements`/잠금 파일과 문서에 기록한다.
- 기존 코드를 불필요하게 통째로 교체하지 말고 단계별로 확장·리팩터링한다.
